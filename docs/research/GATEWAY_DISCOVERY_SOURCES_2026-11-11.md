# Дополнительные источники обнаружения VAG — 11.11.2026

## Что реализовано

После завершённого отсутствующего/неподдерживаемого основного UDS-списка
Gateway добавлены отдельные read-only источники:

| Запрос | Формат | Смысл записи |
| --- | --- | --- |
|222A2A |Список однобайтовых логических адресов |Gateway сообщает установленный логический блок |
|22F1B7 |Двухбайтовые big-endian адресные индексы |Сопоставление только с известными маршрутами; неоднозначные владельцы остаются кандидатами |
|2204A3 |32-byte bitmap для подтверждённого common-семейства |Запись кодировки, пока не доказательство присутствия |
|222A28 |32-byte bitmap того же семейства |Признак события, пока не собственная память DTC |

Работающий прежний список не получает дополнительных проб. Сначала
сохраняется прежний путь1A9F/04A1/2A26 и выбор формата по Gateway. Новая
ветвь не выполняется в незавершённом functional/pending обмене. Это
расширение существующего сканера, не замена работающего транспорта.

Все запросы разрешены фиксированным списком чтения. NO DATA и законченный
NRC11/12/31 допускают следующий источник; NRC33/прочие отказы не считаются
неподдерживаемым DID. Повреждённые данные, IO и отмена не переключают на
следующий список. Сохраняются ограничения общего UDS приёма и восстановления.

## Полнота, адреса и счётчики

Происхождение записывается отдельно от факта ответа ECU. Кодировка/событие
без собственного ответа остаётся CANDIDATE; происхождение остаётся в note
и журнале после неудачного чтения. DTC/COMPLETE появляются только после
валидированного ответа своей памяти. Само событие Gateway не создаёт DTC.

Повторяющиеся ID/индексы объединяются. Конфликт маршрутов запрещает опрос.
Неизвестные логические ID видны без выдуманного адреса; неизвестные индексы
дают ограничения полноты. Индекс не превращается в произвольный CAN ID:
разрешены только сопоставленные фиксированные маршруты.

Логические01/02/51 имеют известные варианты11-bit/29-bit под одним ID.
Один положительный путь завершает собственное чтение, ошибки не публикуются
повторно под техническим маркером. FE/FF из прежнего внутреннего каталога
не интерпретируются как физические endpoint из однобайтового списка.
Новые альтернативы используются только при подтверждённом списке.

Если отдельное основание уже разрешало полный фиксированный каталог
платформы, подсказки его не сужают. Если основание только в подсказках,
опрос ограничен этими известными маршрутами и Gateway. Успешное чтение
нескольких кандидатов не объявляет полный installation list полученным.

После короткой процедуры списка блоки читаются по одному, вместе с DTC.
Нет отдельного предварительного прохода presence по всем ECU перед DTC.
Профильный тест проверяет порядок собственных DTC19→16→03, включая CAF1,
raw CAN,STN иVT. Старые источники и TP2.0 не переписаны.

## Ограничения и проверка

Схемы восстановлены по статическому пути сравнительной реализации; новых
автомобильных ответов этих DID пользователь не предоставлял. Кодировка и
events bitmap включены только для подтверждённого common-формата32bytes.
Другие семейства/расширенные логические namespace не угадываются.
Пустой корректный список позволяет продолжить обнаружение, но сам не
доказывает установленные ECU. Неверные DID/байты/нечётный индекс/размер
отклоняются; ответы и ограничения сохраняются.

Новые25 профильных тестов прошли:12 разборщиков/слияния/namespace,
6 выбора источника/границ и7 сквозных сценариев. Проверены неподдерживаемые
ответы, повреждённые данные, отказ доступа, IO, отмена, смешанные сведения,
разные режимы CAN, собственные DTC29-bit и сохранение прежнего каталога.
Первый новый профильный прогон14 дал1 отказ из-за неверного bit в тесте;

Эти промежуточные прогоны не являются окончательными успешными проверками.
