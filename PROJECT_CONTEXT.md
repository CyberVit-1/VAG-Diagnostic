# PROJECT_CONTEXT.md — VAG Diagnostic

**Дата:** 2026-10-22  
**Текущая версия исходного проекта:** 0.1.1 (исправление обработки реального CAN-ответа)  
**Статус:** версия 0.1.0 успешно собиралась в GitHub Actions; **аппаратное испытание 0.1.0 выполнено 2026-10-22** с физическим Wi-Fi ELM327. Доказано: транспорт и AT-команды работают, автомобиль реально ответил двумя OBD-II CAN-кадрами. Выявлены и исправлены в исходниках 0.1.1 ошибки распознавания слитных CAN-кадров и маскирования протокольных строк как VIN. **Аппаратное испытание 0.1.1 ещё не проведено**; новую сборку и тесты нужно подтвердить отдельным CI-запуском.

## Цель
Android-приложение для диагностики автомобилей Volkswagen Group с честным отображением достоверно прочитанных неисправностей и постепенным расширением от OBD-II до платформо-специфичного VAG Auto-Scan.

## Архитектура
- `ui/` Compose Material 3, навигация страниц, expandable ECU cards, тёмная/светлая темы.
- `MainViewModel.kt` orchestration, `StateFlow`, отмена и сохранение частичных результатов.
- `transport/Links.kt` `ElmLink`: Wi-Fi TCP (SocketFactory конкретной сети), BT Classic SPP, BLE Nordic UART (NUS).
- `transport/ElmEngine.kt` сериализованный обмен с ELM327, AT-инициализация, реальное ожидание prompt `>`.
- `core/DiagnosticCore.kt` чистые Kotlin парсеры ELM/ISO-TP/OBD DTC и UDS 59 02; **UDS не привязан к интерфейсу**.
- `data/` Room: журналы и история с сохранением между запусками. DataStore: настройки соединения.
- `MainActivity.kt` разрешения, внешний поиск Яндекса, экспорт TXT с маскированием VIN.

## Инженерные правила и навык разработки

- `AGENTS.md` — обязательные правила разработки, безопасности, журналирования, сохранения транспорта и отчётности.
- `.agents/skills/vag-diagnostic/SKILL.md` — повторно используемый навык VAG Diagnostic Engineering с процедурой исследования, правок, сборки, тестирования и проверки на физическом ELM327.
- Добавление инструкций **не меняет диагностический код и номер версии 0.1.0**. Само наличие файла навыка не подтверждает его автоматическую загрузку во всех клиентах ChatGPT; в совместимой рабочей среде агенты могут использовать файлы репозитория.
- Для создания и сохранения этих правил **ничего от пользователя не требуется**. Следующий аппаратный шаг остаётся прежним: испытание конкретного APK на автомобиле с журналами.

## Реализовано в исходном коде (НЕ означает аппаратное подтверждение)
- Ручное Wi-Fi/TCP соединение с поддержкой изолированной сети ELM327.
- Сопряжённые Bluetooth SPP устройства и подключение.
- BLE сканирование и профиль Nordic UART Service. Прочие реализации BLE UART не поддержаны.
- Инициализация ELM327; `0100` для проверки ответившего OBD ECU, `ATDPN` для определения протокола.
- Чтение Mode 03, 07, 0A с проверкой позитивного SID и DTC count для CAN.
- Разбор CAN Single Frame и raw ISO-TP First/Consecutive, контроль последовательности и неполноты.
- OBD-II ответчики отображаются как OBD, не выдаются за все блоки VAG.
- История и экспорт журнала, карточки со статусами, анимация разворачивания.
- Локальные описания для ограниченного набора P-кодов, поиск Яндекса по нажатию.
- Команд записи/очистки DTC нет.

## Реальное испытание 0.1.0 и дефекты (22 октября 2026)

- Получены скриншот экрана подключения и экспорт TXT после двух попыток.
- Wi-Fi TCP соединение установилось с физическим адаптером, ATZ / ATE0 / ATL0 / ATS0 / ATH1 / ATSP0 / ATAT1 получили ответы.
- В обоих сеансах команда `0100` получила два корректных CAN-ответа: `7E8064100BE3EA813` (адрес 7E8, payload `41 00 BE 3E A8 13`) и `7E906410098188001` (адрес 7E9, payload `41 00 98 18 80 01`).
- Парсер 0.1.0 распознавал только CAN-заголовок с пробелом; поэтому ошибочно сообщал `Неизвестная строка адаптера` и не подтверждал связь с автомобилем.
- Экспорт 0.1.0 заменил реальные слитные CAN-кадры строками `[VIN REDACTED]`, так как без контекста принимал каждую 17-символьную последовательность за VIN. Исходные кадры сохранились на скриншоте.
- Две команды `0100` — **не две завершённые диагностики**. Команд `03`, `07`, `0A` в журнале нет; наличие/отсутствие DTC этим испытанием **не подтверждено**.
- В 0.1.1 добавлены обработка слитного 11-битного CAN-заголовка, форматирование компактного payload перед парсингом, контекстное VIN-маскирование с сохранением CAN-кадров и JUnit-проверки на реальных строках.
- **Фактически подтверждено на автомобиле только в 0.1.0:** Wi-Fi TCP/AT/ответы на 0100; исправленное распознавание в 0.1.1 пока подтверждено только реализацией и ожидает тестов и нового аппаратного испытания.
- Модель автомобиля и модель адаптера не требуются для исправления этих ошибок и не должны превращаться в жёсткую привязку приложения.

## НЕ реализовано / НЕ подтверждено
- **Debug APK собран в GitHub Actions** (Android SDK 35, Gradle 8.11.1, JDK 17), запуск №39628972361 завершён успешно, артефакт сохранён. Исходный архив не содержит `gradle-wrapper.jar`, поэтому CI использует установленный Gradle. APK **ещё не испытан** на Android-смартфоне и автомобиле.
- Физический тест **Wi-Fi в версии 0.1.0 выполнен**: два реальных CAN-ответа; SPP/BLE и версия 0.1.1 на автомобиле **не проверены**.
- Не реализованы VIN, платформа, чтение Gateway 19, Installation List, VAG Auto-Scan.
- Не реализованы полноценные сеансы UDS / KWP2000 / KWP1281 / VW TP 2.0.
- Нет сети лицензированных онлайн описаний DTC и кэша с источником; только локальная ограниченная база и браузер Яндекса.
- Нет проверки полного жизненного цикла на реальном смартфоне, BLE NUS ограничен совместимым GATT-профилем.
- Протоколы кроме ISO 15765-4 могут потребовать дополнительной поддержки нестандартных заголовков для достоверной идентификации ECU.
- Заложена сохранность уже накопленных логов; миграции Room потребуется писать при изменении схемы.

## Правила и решения
1. Нельзя маркировать неподтверждённый ответ как `Ошибок нет`.
2. Нет бесконтрольного перебора адресов CAN и подозрительных диагностических команд.
3. Все ошибки транспорта и неполные записи сохраняются в журнал (в том числе при сбое DTC).
4. Выбор Wi-Fi TCP через `Network.socketFactory`, никогда не `bindProcessToNetwork` для всего приложения.
5. Сохранить source-of-truth в Room, не стирать историю при обновлениях.
6. Каждый протокол/транспорт проверять отдельно на реальном автомобиле.
7. Поддержку полного VAG Scan добавлять только через проверенный профиль платформы и адресов.
