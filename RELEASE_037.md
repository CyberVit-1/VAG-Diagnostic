# 0.3.7 / 23 — объединённый read-only сценарий VAG CAN

Реализована общая цепочка подключения, обнаружения ECU и чтения DTC через TP2.0/UDS на существующих байтовых транспортах ELM. Итоговые сборка,219тестов, [GitHub CI41066308723](https://github.com/CyberVit-1/VAG-Diagnostic/actions/runs/41066308723) и проверка настоящего APK успешны. Допускается один объединённый кандидат для автомобиля; промежуточные внутренние APK не выдавались.

## Изменения

- Выбор протокола, кэш ответа/идентификации и формат DTC определяются для каждого ECU. Номер детали центральной электроники используется для выбора применимых процедур. Идентификация содержит проверяемую часть номера/ПО/компонента и полные ответы подсистем.
- Installation List: многосообщенческие 1A9F/04A1, шесть карт 2A26, функциональный запрос 700 и раздельное объединение владельцев19/42/52/09. Неизвестные позиции и пропущенные ожидаемые списки оставляют охват неполным. Биты установки или индикации неисправности не заменяют чтение DTC.
- Фиксированный опрос09 выполняется и вне исходного списка. Дополнительная процедура61 использует реальный ответ ECU; отсутствие ответа не добавляет блок.
- Если для подтверждённого производителя VAG список недоступен или Gateway не отвечает, после фактического адресного OBD-ответа проверяется полный фиксированный каталог189кандидатов, включая30расширенных логических ID. Кандидат становится найденным только после ответа ECU. Неответивший Gateway не объявляется найденным. Для неопределённой платформы без подтверждённой марки обязателен настоящий список. Никакого произвольного перебора CAN-ID.
- Физический flow control использует собственный TX ECU в11/29битах. Поздние ответы после ResponsePending собираются без повтора запроса, включая FF/CF, с проверкой адреса, типа кадра, SID/DID, длины, последовательности и конечных сроков.
- При чистом A8 до DTC старое соединение закрывается, создаётся новый транспорт, подтверждается0100 и продолжается очередь. Повтор ECU ограничен одним, восстановлений не более четырёх. Повреждённый/pending поток не используется для новых запросов. Сбой восстановления настроек запрещает1001 на неверном адресе.
- Полученные DTC сохраняются до необязательных действий и переживают сбой завершения сессии. Подключение без VIN проверяется реальным адресным0100; это не выдаётся за подтверждение многофреймового обмена.
- Сводка остаётся сворачиваемой. Неподтверждённые кандидаты сгруппированы и по умолчанию скрыты; подтверждённые, но не ответившие ECU остаются в основном списке. Развёрнутый список использует ленивую загрузку карточек.
- VIN отображается локально; защита экспорта сохраняется. Фактический VIN не включается в исходники, тесты или документацию.

## Уровни проверки

Последнее физическое испытание остаётся0.3.6/22:18ID,11полных чтений, закрытие канала62 до DTC;04/46 не ответили, OBD восстановлен. Это не результат0.3.7. Причина отсутствия ответа04/46 и самостоятельность этих ECU не доказаны; чужие DTC в них не копируются.

Итоговая локальная проверка0.3.7/code23: Android assembleDebug и219тестов прошли без ошибок. Полный резервный каталог проверен синтетическими сценариями: расширенный ECUFFFF с DTC, молчание остальных, отсутствие Gateway, запрет неподтверждённой платформы, повреждение и отмена. Чистый A8 во время получения списка также требует нового транспорта/подтверждённого0100 перед резервным опросом. Исходные автомобильные записи сохранены; новые настройки, присутствие и продолжение после восстановления явно обозначены как программные адаптации/синтетические продолжения. GitHub CI и сведения о настоящем артефакте фиксируются в PROJECT_CONTEXT.md отдельно.

Аппаратно новые пути не подтверждены. Поддержка BLE ограничена NUS; KWP1281, CAN FD и DoIP не заявляются. Работа на каждом поколении VAG и каждом клоне ELM не гарантируется программными тестами.

## Внимание: сохранность данных

Пакет остаётся `com.vagdiagnostic.app`, Room version1, разрушительных миграций нет. Подпись проверенного APK отличается от переданной0.3.6: обычное обновление поверх неё не выполнится. Установка использует прежний пакет, отдельного параллельного приложения не будет. Удаление прежней установки стирает её внутреннюю историю, журналы и настройки.

До любых действий с заменой приложения экспортировать нужные TXT во внешнее хранилище и проверить, что файлы открываются. TXT сохраняет диагностический журнал, но не восстанавливает всю базу истории/настройки. Сведения о подписи конкретного передаваемого APK проверяются отдельно; сохранность внутренней истории при переустановке не обещать.

## Одно следующее испытание после проверки APK

На стоящем автомобиле с включённым зажиганием выполнить одно обычное сканирование, дождаться окончания или явного сообщения об остановке, экспортировать новый TXT. Специальная пауза20–30секунд не требуется. До передачи проверенного APK ничего от пользователя не требуется. Следующий инженерный шаг — анализ действительного журнала0.3.7 по всей очереди, обнаружению и DTC.
