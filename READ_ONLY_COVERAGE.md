# Проверка подключения, обнаружения ECU и чтения DTC

Срез 30.10.2026. Это карта реализации и программной проверки CAN/TP2.0/UDS,
а не утверждение об успешном чтении всех ECU на реальном автомобиле.
Число найденных блоков не задано заранее.

| Этап | Реализация и границы |
| --- | --- |
| Транспорт и начальный обмен | Независимые Wi-Fi TCP через Network.socketFactory, SPP и BLE/NUS; один последовательный поток команд, проверка AT и фактического OBD-ответа. Получение VIN не является обязательным условием OEM-опроса. |
| Gateway | TP2.0 1A9F с переходом на 04A1 только по завершённому неподдержанному сервису; UDS-идентификация, шесть семейств bitmap, функциональные карты 2A26 с раздельной сборкой ответов владельцев. Неизвестные биты остаются ограничением списка. |
| Поиск без списка | Фиксированный каталог 189 ненулевых логических кандидатов; разрешение по подтверждённой платформе из VIN либо поддерживаемому номеру Gateway. Произвольного перебора CAN ID нет; молчащий кандидат не становится найденным ECU. |
| Выбор протокола ECU | Маршрут из фактической карты имеет приоритет; отдельный кэш присутствия/протокола/идентификации каждого ECU. Независимая проверка 09 и дополнительная фиксированная процедура 61; отрицательные ответы не превращаются в нулевые DTC. |
| TP2.0 | CHANNEL SETUP, параметры, ACK, последовательности, многочастные ответы, pending, закрытие. Чистое A8 до прикладного ответа требует нового транспорта и проверки OBD; полные DTC сохраняются до дополнительного чтения. Штатное закрытие после полного служебного ответа допускает ограниченное открытие нового канала. Повреждённый обмен не переиспользуется. |
| Физический UDS | Точные 11/29-битные адреса и flow control, проверка SID/DID/подфункции, поздних FF/CF и ResponsePending, ограниченные таймауты, восстановление адресации перед завершением сессии. |
| Идентификация | KWP 1A9B и сообщения подсистем; допустимый F187 fallback. UDS F187/F197/F189/F19E, ASAM/revision по необходимости, сырой статус 0174; подтверждённые поля сохраняются до следующего запроса. Подсистема не выдаётся за отдельный ECU. |
| Основная память ошибок | KWP capability 31B80000 выбирает 1800FF00/1802FF00; UDS 19028D. Полные коды и OEM-статусы проверяются и сохраняются. OBD 03/07/0A учитываются отдельно. |
| Дополнительные записи | Только для реально прочитанного DTC: KWP 120004+код16, UDS 1906+код24+FF. KWP: 37 фиксированных типов и два текстовых. UDS: ASAM/revision, 37 специальных типов и 23 поля общих схем. Сохраняются байты и маскированные числовые поля; неизвестная схема остаётся непрочитанным хвостом. Единицы и описания не угадываются. |
| Ошибки дополнительных записей | Полный ответ с неверной структурой получает INVALID_RECORDS и не останавливает следующие ECU. Чужой сервис/код, незавершённый pending, повреждённый транспорт и IO сохраняют основной результат, но прерывают недостоверный обмен. |
| Защита доступа | 22539B только читает статус. По указанию пользователя сейчас исключены Security Access, SFD unlock, запись для отключения фильтра, кодирование, адаптации, исполнительные тесты и стирание DTC. Защищённый ECU может остаться недоступным. |
| Данные и интерфейс | Частичные результаты, RAW-журнал, сворачиваемая сводка; кандидаты отделены от подтверждённых ECU. VIN разрешён локально, экспорт маскирует его. Room v1 и постоянный package com.vagdiagnostic.app сохраняются. |

Аппаратные границы: KWP1281/K-line, DoIP, CAN FD и произвольные BLE-профили
этим срезом не реализованы. Работа SPP/BLE и новых ветвей требует отдельных
физических подтверждений. Нельзя обещать чтение защищённого, физически
недоступного или неподдерживаемого данным адаптером блока.

Последний физический журнал остаётся 0.3.6: 18 ID в списке Gateway, 11 полных
чтений, закрытие канала 62 остановило очередь. Новая реализация этого
исправления проверяется программно. 04/46 по последнему журналу не ответили;
их самостоятельность или виртуальность не доказана, ошибки других ECU в
них не копируются. Повторное чтение ранее доступных блоков — проверка
регрессии, а не предел разработки.
