# Проверка памяти DTC после молчания служебных запросов — 07.11.2026

Внутренняя разработка поверх программно проверенного53e1dde и документации
97eccdb. Новая пользовательская версия не назначена, APK не выдаётся.

## Найденный барьер

В фактическом журнале0.3.13 для04 и46 нет ответа на TP2.0 CHANNEL SETUP,
затем на известном UDS-маршруте не отвечают3E00,1003 и22F187.
Прежний `Uds.openOnce` после этого выбрасывал `UdsNoResponse`, поэтому
основной19028D не отправлялся вообще. Это подтверждённое поведение кода
и журнала; оно не доказывает, что молчащий ECU ответит на19028D.

## Сравнение с открытой реализацией

[udsoncan Client](https://udsoncan.readthedocs.io/en/latest/udsoncan/client.html)
и [его исходник](https://github.com/pylessard/python-udsoncan/blob/master/udsoncan/client.py)
разделяют открытие транспорта и отдельные диагностические сервисы.
`Client.open` открывает соединение; чтение DTC не требует предварительного
чтения номера детали. Операция чтения может получить собственный
положительный, отрицательный, повреждённый ответ или timeout. Это не
гарантия, что всякий VAG разрешает0x19 в default session.

Выбранное изменение нашего планировщика — инженерная адаптация этого
разделения, а не утверждение о полном переносе чужого готового стека.
В TP2.0 транспортный канал обязателен: нельзя отправлять KWP DTC без
подтверждённого CHANNEL SETUP и известных динамических CAN-адресов.

## Ограниченный дополнительный путь

Только если Gateway уже подтвердил список и этот ECU входит в него,
допускается ограниченное чтение19028D на заранее проверенном UDS-маршруте
после завершённых молчащих служебных запросов. Конфликтные/неизвестные
маршруты по-прежнему не опрашиваются. Для кандидатов без подтверждённого
списка новое разрешение не действует. На стадии самого обнаружения
Gateway поведение не ослаблено.

Открытие такого пути возвращает явное отсутствие подтверждённого ответа;
запись Gateway сама по себе не становится RESPONSE. Только собственный
фактический ответ на0x19 подтверждает отвечающий ECU. Полный положительный
ответ проходит тот же строгий парсер DTC; отрицательный ответ не считается
нулём ошибок. Два завершённых NO DATA остаются неудачным чтением, после
которого можно пробовать только уже известные варианты того же ECU и
продолжать очередь. Новых CAN ID и параллельных запросов нет.

Pending, повреждённая/незавершённая транзакция, BUFFER FULL, отмена и
потеря физического потока не разрешают этот дополнительный запрос.
Если расширенная сессия не подтверждена, фиктивный возврат1001 не отправляется.
Стирание, Security Access, SFD, coding/adaptation и изменения ECU отсутствуют.

## Проверки и границы

До изменения два новых сценария падали: DTC-only ECU не читались вообще,
а проверка полностью молчащих ECU обнаруживала отсутствие самой DTC-попытки.
Проверка запрета такого расширения для кандидата без списка проходила.
После изменения все три прошли. DTC-only сценарий проверяет04,16 и46
для CAF1, RAW, STN и VT, с собственными пустыми и непустыми DTC-ответами.
Это синтетические ответы, не автомобильное доказательство.

Добавлены проверки NRC33, неправильной подфункции, неполной группы DTC и
повреждённого служебного обмена. Первый полный прогон479 выявил четыре
исторических реплея без новых запросов и один неверно настроенный тестовый
инжектор ошибки. Реплеи расширены явно синтетическими NO DATA только после
полностью молчащих служебных запросов; записанные ECU/DTC-ответы не изменены.
Инжектор BUFFER FULL переведён на соответствующий ему CAF1-путь.

После этого девять профильных и реплей-проверок прошли на JVM и в Android
unit,0 failures/errors/skips. assembleDebug прошёл; DEX783/max112/10894,
oversized[]. Результат обоих полных GitHub CI этого исходного среза
фиксируется отдельно, не объявляется заранее. Результат старых474 для
53e1dde не выдаётся за проверку нового кода. Подписи/телефон не проверялись.

На реально молчащем UDS-маршруте появятся дополнительные ограниченные
DTC-запросы. Такой случай может занимать больше времени, чем прежний
ранний выход, зато запрос собственно нужной памяти не пропускается.
Ускорение и успех04/46 на автомобиле пока не подтверждены.
Названия/назначения сохранены из каталога, техническая инвентаризация
и расширенные записи ошибок в обычном сканировании не включаются.

Что требуется от пользователя сейчас: **ничего**. Новый автомобильный
опрос не предлагается на основании только этих программных сценариев.
