# 0.3.9 / 25 — исправление регрессии0.3.8

Внутренний кандидат. До завершения программных проверок и автономного
воспроизведения на Android новый автомобильный тест не запрашивается.
Физическое чтение ECU этой версией не подтверждено.

270тестов JVM прошли без ошибок/пропусков. Полный Android build/test текущей
версии выполняется; CI и автономное подтверждение на телефоне фиксируются
после завершения. Первая полная проверка обнаружила три некорректных ожидания
тестов: глобальный UDS presence включал независимый09, а старая проверка
после обрыва не учитывала новые NOT_QUERIED строки. Проверки уточнены по
фактическому адресу и состояниям; полный270-тестовый прогон повторён успешно.

- Состояние сканирования перенесено в отдельный объект сеанса; обнаружение
  и опрос одного ECU выполняются раздельно. Это устраняет разрастание одного
  coroutine-метода. Исходный0.3.8 воспроизводимо завершался SIGSEGV на Android
  при проигрывании записанного журнала. Контрольный вариант разделения имеет
  максимум53регистра/6892code units вместо838/252786. Повторная проверка
  выполнения на телефоне ещё требуется.
- Точный повтор предыдущего TP-кадра внутри незавершённого пакета не добавляет
  данные повторно и не сдвигает sequence. При необходимости повторяется ACK,
  диагностический запрос не повторяется. Лимит3дубликата; изменённые данные,
  посторонние кадры и повреждённые последовательности остаются ошибкой.
- Для подтверждённого списком CAN-двигателя допускается один новый канал
  через2000мс после полного NO DATA setup или ACK/живого канала без ответа
  на1089. Это не повтор DTC/pending/повреждённого обмена и не инструкция
  пользователю выжидать перед сканированием.
- Весь подтверждённый список Gateway сохраняется до опроса ECU. Не прочитанные
  блоки остаются NOT_QUERIED, без вымышленных DTC или нулевых результатов.
  Молчащие кандидаты по-прежнему не становятся найденными блоками.
- В GitHub CI проверяется бюджет размера методов DEX сканера. Это
  консервативное правило проекта, не доказательство исполнения на Android.
