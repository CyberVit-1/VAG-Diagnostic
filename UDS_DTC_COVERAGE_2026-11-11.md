# Охват признаков UDS DTC —11.11.2026

Внутреннее изменение после0.3.15, без нового пользовательского APK.
Исходное чтение19028D запрашивало признаки01/04/08/80. Оно не запрашивало
02(testFailedThisOperationCycle) и20(testFailedSinceLastClear): запись,
имеющая только такой поддерживаемый признак, могла отсутствовать в ответе.
Это установленный пробел фильтра запроса, не доказанная причина молчания04/46.

Семантика проверена по первичной документации и исходникам открытой реализации:
- [Фильтр reportDTCByStatusMask](https://udsoncan.readthedocs.io/en/latest/udsoncan/client.html#udsoncan.client.Client.get_dtc_by_status_mask): совпадение любого запрошенного бита.
- [Отображение битов Dtc.Status](https://udsoncan.readthedocs.io/en/latest/_modules/udsoncan/common/dtc.html):01/02/04/08/20/80 — признаки сбоя/истории/индикатора;10/40 — незавершённые тесты.

Единая константа1902AF используется основным UDS-чтением, запросом к блоку
из installation list при тихом preflight, повторами, восстановлением,
границами разрешённых команд и именем сервиса результата. AF сохраняет все
биты8D и добавляет02/20. Это один запрос вместо одного, без лишнего прохода.
FF не выбран: только незавершённый тест не должен запрашиваться как ошибка.
Отказ на AF остаётся отказом: автоматического запроса с урезанной маской,
скрывающего возможные ошибки, нет. Неполные ответы/NRC/NO DATA не становятся нулём.

Статусы02/20 показаны словами с учётом объявленной ECU availability mask.
Исторический сбой не объявляется текущей или подтверждённой ошибкой.
Пустой положительный ответ без поддержки хотя бы одного признака изAF
отклоняется на уровне чтения OEM-памяти: отсутствие совпадающих поддерживаемых
признаков не доказывает чистую память. Сырые байты статуса сохраняются.
Универсальный декодер исторических ответов и KWP18 не переписаны.

Проверка всех256 status bytes отделяет шесть признаков неисправности от
readiness-only. Сквозной тест читает02/20 поCAF1/raw/STN/VT, проверяет
ровно один DTC-запрос и отсутствие8D. Исторические replay TSV не изменены:
адаптация запроса8D→AF явно синтетическая, ECU payload сохранён и не является
физическим свидетельством ответа наAF. Полные результаты будут записаны
после завершения проверок окончательного source.

Новые Gateway-источники предыдущего этапа сохранены. Подключение к адаптеру,
Wi-Fi/SPP/BLE, Room, версия и правила конфиденциальности не меняются.
Физический охватAF, в том числе04/46, не подтверждён. Ничего не требуется.
Далее — общий анализ результата чтения и маршрутов молчащих блоков перед
единой автомобильной сборкой, без поездки после каждого локального изменения.
