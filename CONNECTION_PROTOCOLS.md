# Подключение и OEM-диагностика — 0.3.0

## Адресация

Пользовательский VAG ID, TP2.0 destination и UDS CAN request/response — независимые поля. В текущем legacy-профиле Gateway VAG 19 имеет TP2.0 destination 1F, setup TX 200 и setup RX 21F. Старые версии 0.2.2–0.2.4 ошибочно использовали 19C0/219. Отсутствие ответа на тот запрос не доказывает ограничения адаптера. Динамические CAN IDs после D0 берутся из ответа ECU.

## Соединение

Реализованы: CAN 6 с headers, CAF0/CFC0 и variable DLC; C0/D0; A0/A1 с A00194FF82FF; параметры T1/T3; sequence/ACK; A3/A1; A8. Запросы ограничены read/session/identification allowlist. Перепутанные, неполные и посторонние кадры отвергаются. OEM-запросы после IOException не повторяются на том же потоке.

Ожидание ELM до prompt ограничено коротким окном: начальное ATST10 = 64 мс; после согласования окно выводится из T3 с запасом. Окно вместе с паузой перед ACK не превышает 160 мс при объявленном T1 200 мс; неподдержанные сочетания отклоняются. Записи RAW временно буферизуются до завершения канала, включая ошибку/отмену, чтобы Room не задерживал ACK. Сохраняются исходные метки времени обмена. Это программная мера; реальные задержки адаптера и Android требуют автомобильного испытания.

Для известного эквивалентного UDS-маршрута используется ISO-TP и подтверждение read-сессии 1003; завершение 1001. OEM-работа выполняется в одноразовом ELM-сеансе, затем создаётся и проверяется штатный OBD-сеанс. При Stop скрытого reconnect нет. Диагностика общая для Wi-Fi/SPP/BLE; драйверы транспорта не переписаны.

## Список блоков и неисправности

Проверяются 1A9F и альтернативный 2204A1 с echo, длиной и структурой записей. Неизвестный ID из положительного списка сохраняется, но не получает выдуманного CAN-маршрута. Если список недоступен после подтверждения Gateway, используется ограниченная таблица из 14 известных кандидатов. Кандидат не считается установленным до ответа.

Чтение DTC: 1800FF00 для powertrain, 1802FF00 для legacy OEM, 19028D для UDS. Сохраняются исходный код и статус; неизвестные биты не получают предположительной расшифровки. NO DATA, отрицательный ответ и обрезанный payload не равны нулю неисправностей.

## Хранение и интерфейс

Generic OBD и OEM результаты остаются раздельными. При наличии VAG-результатов основные счётчики относятся к VAG, чтобы не складывать два адресных представления одного ECU. Статус кандидата явно виден. Частичные результаты сохраняются после каждого блока, Stop и ошибки связи.

Room schema остаётся v1. Поля source и statusText добавлены в существующий JSON с defaults для старой истории. applicationId прежний com.vagdiagnostic.app. У нового debug APK может отличаться подпись: uninstall стирает Room и настройки; TXT не полная резервная копия.

## Границы и проверки

- Включён текущий платформенный гейт VW/1K и 14 явно заданных маршрутов.
- Другие платформы и part-number-dependent UDS bitmap mappings пока не включены.
- BLE сейчас только NUS. Ни новый OEM-путь, ни Bluetooth-транспорты пока не подтверждены физическим испытанием этой версии.
- Нет произвольного CAN sweep, Security Access, очистки DTC, кодирования, адаптаций, программирования или actuator tests.
- Сценарные проверки охватывают segmented TP2.0 list/ACK, per-ECU DTC, UDS fallback, неверные адреса и sequence, IOException без продолжения на сломанном потоке, Stop до следующего ECU, отрицательные и неполные записи.
- Моделируемые ответы и успешная сборка не являются аппаратным подтверждением. Текущий статус CI фиксируется в PROJECT_CONTEXT.md.
