# VAG Diagnostic 0.2.2 (TP2.0 Gateway 19: ограниченная проверка канала)

**Исходный Android-проект**, Kotlin + Compose + Material 3, read-only OBD-II. Это экспериментальная база для испытаний на автомобиле, а не готовая подтверждённая VAG Auto-Scan программа.

## Содержимое
- `app` — Android приложение (Wi-Fi TCP, Bluetooth SPP, BLE/NUS, OBD-II Mode 03/07/0A).
- `PROJECT_CONTEXT.md` — актуальное состояние, ограничения и дальнейшие шаги.
- `RESEARCH.md` — 10 алгоритмов, источники и уровень достоверности.
- `BUILDING.md` — установка инструментов, сборка и проведение первого испытания.
- `tools/DiagnosticCoreSmoke.kt` — локальная проверка протокольного парсера.

## Правила разработки

Для продолжения проекта в совместимой среде кодового агента используйте
[`AGENTS.md`](AGENTS.md) и
[**VAG Diagnostic Engineering**](.agents/skills/vag-diagnostic/SKILL.md).
Они задают порядок работы с ELM327, правила read-only диагностики,
сохранение журналов, защиту от регрессий и обязательную проверку функций
на реальном автомобиле. Сейчас версия 0.1.1.

## Ключевые ограничения
- Стандартные OBD-II DTC **не** эквивалентны полному списку неисправностей VAG.
- В 0.1.1 нет поддержки VAG Installation List, полноценного UDS/KWP/TP2.0; обнаруженные единицы — только ответчики OBD.
- Для CAN декодирования используется count byte; для старых OBD-протоколов без count — пары DTC.
- Если автомобиль не ответил по режиму, статус неполный/нет ответа, не `Ошибок нет`.
- Версия 0.1.0 реально получила два CAN-ответа на `0100`, но из-за ошибки парсера не запустила чтение DTC. Исправление 0.1.1 прошло GitHub Actions, **на автомобиле ещё не проверено**.

## Подготовка к следующему аппаратному испытанию (0.1.3)
- Не просим проверять каждый промежуточный коммит на автомобиле. Сначала программные проверки полного цикла ELM, обработка тайм-аутов и обрывов.
- `ElmScanSession` при длительном Wi-Fi простое переоткрывает и проверяет сессию до начала сканирования; одна ограниченная реактивная попытка восстановления после I/O ошибки.
- Bluetooth SPP/BLE не менялись; функции полной VAG-диагностики не реализованы.
- Внимание: 0.1.3 debug ставится рядом с 0.1.1/0.1.2 под отдельным `applicationId` `com.vagdiagnostic.app.pilot3`. Установленные версии и данные сами не удаляются; новая история пустая. Удаление старой версии вручную стирает её внутренние данные, поэтому сначала экспортируйте TXT, если они вам нужны.

## Главный промпт и обязательные правила
- Весь [пользовательский мастер-промпт](MASTER_PROMPT.md) (15 разделов, 676 строк) сохранён без сокращений и дословно включён в [AGENTS.md](AGENTS.md).
- Каждый этап: инженерное исследование → реализация → проверка полного пути соединения/диагностики и отказов → сборка → один консолидированный запрос на испытание с физическим адаптером, когда сборка готова.
- Начиная с 0.1.4 используется один постоянный Android package ID `com.vagdiagnostic.app` без `pilotN`; предыдущие тестовые приложения пользователь удаляет при необходимости после экспорта TXT.
- Debug-подпись может отличаться между сборками; удаление старого приложения стирает внутренние данные, но не ранее сохранённые внешние TXT.

## Стабилизация 0.1.5
- Проверки окончания AT-команд: без ELM-промпта сеанс прерывается, завершённый `?` допустим для опциональных команд.
- Поддержка компактных диагностических CAN заголовков 29 бит; слитные 11 бит из реального журнала сохранены.
- Параметры повторного подключения берутся от активного сеанса; неполные чтения DTC корректно отражаются в истории; TXT подписан действующей версией.
- Постоянный Android package ID `com.vagdiagnostic.app`. Реальный аппаратный тест будет запрошен только после программной стабилизации.

## Итоги реального испытания 0.1.5 и изменения 0.1.6
- **Физически подтверждены:** Wi-Fi ELM327, восстановление после 32-секундной паузы, два OBD-II CAN ответчика, корректные ответы на DTC режимы 03 и 07 (в обоих 0 записей). Это не полный VAG Auto-Scan.
- **Не подтверждено:** режим постоянных DTC 0A (`NO DATA`); отсутствие ответа не доказывает отсутствие постоянных неисправностей или отсутствие поддержки режима.
- 0.1.6 уточняет экран: показывает числа подтверждённых ответов отдельно для 03/07/0A, «Все режимы» и «Частично». Неполный диагностический ответ больше не выводится как глобальная красная транспортная ошибка на остальных экранах.
- Транспорт и ранее подтверждённое восстановление TCP остаются без изменений. Повторный автомобильный тест только ради этих UX изменений не требуется.


## Этап 0.1.7 — UDS/ISO-TP и безопасный барьер Gateway 19

- Добавлен `VagUdsReadOnly`: чистый валидатор `19 02` (ответ `59 02`), сохраняет оригинальный 24-битный DTC и `DTCStatusAvailabilityMask`, различает ECU отказ `7F 19 NRC` и `0x78 response pending`, отвергает некорректную длину и чужие ответы. Прежний `UdsDecoder` теперь использует общий валидатор.
- Добавлены сценарные проверки ISO-TP First Frame/Consecutive Frame, последовательностей, неполных фреймов, нулевых DTC, нескольких DTC и неверного ECU.
- Добавлен **барьер `VagGatewayReadiness`**: необходима подтверждённая CAN-связь, проверенная адресация и документированный DID установки конкретной платформы, а также проверенный адресный ISO-TP транспорт. Без этого шлюз не опрашивается.
- **В данной версии запросов Gateway 19 нет.** Ни по умолчанию, ни по неизвестным CAN ID / DID. Реальный ELM327 к этому типу запросов ещё не испытывался.
- Существующий работающий OBD-II путь 0100, 03, 07, 0A, а также Wi-Fi переподключение, SPP и BLE в этом этапе не модифицируются.
- Новое автомобильное испытание только ради чистого UDS декодера не требуется. 

 
## Этап 0.1.8 — строгая адресная CAN-диагностика (пока без отправки)

- `VagAddressedCan` строит только проверенный план адресного
  `UDS 19 02 FF` с ELM `ATSH`, `ATCRA`, `ATCAF1`, `ATCFC1`.
  По умолчанию запуск блокирован без доказанной адресации и
  поддержки адресного ISO-TP конкретным физическим адаптером.
- `decodeSingleEcu` строго собирает фрагменты ISO-TP, ELM
  CAF1 номерные строки, заголовки 11/29 бит и CAN DLC.
  Отклоняет неверные CAN ID, обрыв сообщения и ошибочную
  последовательность, не придумывая 24-битные DTC.
- `interpretGatewayDtcReply` объединяет эту проверку с UDS
  `59 02` и ответом отказа `7F 19 NRC`.
- Текущий реальный автомобильный тест по-прежнему относится
  к версии 0.1.5 и к стандартным OBD-II режимам `03`, `07`.
  Из-за дополнительной библиотеки не требуется новая поездка.

 
## Этап 0.1.9: общий диагностический стек Wi-Fi / Bluetooth Classic / BLE

- Все транспортные реализации используют один `ElmEngine`, `ElmScanSession`, разбор OBD, ISO-TP и UDS; диагностический сценарий не привязан к Wi-Fi.
- При обрыве в ходе только read-only запросов `0100/03/07/0A` для Wi-Fi, SPP и BLE/NUS выполняется одна ограниченная попытка открытия нового соединения и подтверждения автомобиля; для BLE учитывается закрытый канал уведомлений. Предварительное обновление *простаивающего* TCP применяется только к Wi-Fi.
- В тестах проверяются три варианта транспорта, повторное подключение, ограничение попыток и защита от команд записи. Это **не** равно физической проверке SPP и BLE.
- Ручная кнопка проверки AT-режима из UI убрана; внутренний модуль остаётся в проекте, но не запускает незапрошенный активный тест при подключении.
- Режим Gateway 19 не включён, непроверенные адресные UDS запросы не посылаются.

## 0.2.0 — проверка ISO-TP на стандартном OBD, универсально для ELM

- После `03/07/0A` приложение автоматически запрашивает стандартный
  `0900`; лишь при подтверждённой поддержке VIN PID02 запрашивает
  `0902` и проверяет целостность многофреймового ответа.
- При доказанном `7E8–7EF` и подходящем 11-битном CAN
  приложение в новом временном ELM-сеансе проверяет AT-команды,
  адресный стандартный `0902` и затем восстанавливает штатный OBD.
  Разница между принятым AT и реально подтверждённым ответом показана
  в отчёте. В пользовательском интерфейсе нет отдельной тест-кнопки.
- Поддержаны Wi-Fi, Bluetooth Classic, BLE/NUS с одним
  диагностическим алгоритмом. Физически пока проверен только
  Wi-Fi-путь прежней версии.
- **Всё ещё не реализовано:** OEM Gateway 19 Installation List и VAG
  Auto-Scan; ни адреса, ни DID конкретного шлюза не угадываются.
- Для проверки этой новой функции нужен один реальный тест:
  соединение → 20–30 секунд ожидания → сканирование →
  экспорт полного TXT и скриншот после завершения.

## Испытание 0.2.0 на автомобиле 24.10.2026

Физический Wi-Fi ELM327, TXT и скриншот от пользователя:
- 41,676 мс простоя → WIFI_IDLE_REFRESH → подтверждённое новое OBD-соединение.
- 0100: оба ответчика 7E8 и 7E9.
- 03: 2/2, 0 DTC; 07: 2/2, 0 DTC.
- 0A: NO DATA, **не подтверждено**; не интерпретировать как отсутствие постоянных DTC.
- 0900: PID02 поддержан у 7E8; полный сегментированный 0902/49 02 подтверждён у одного ECU.
- ATCAF1, ATCFC1, ATSH7E0, ATCRA7E8 → OK, адресный стандартный OBD 0902 →
  многофреймовый корректный ответ. ADDRESSED_OBD_ISOTP=CONFIRMED.
- После проверки штатный 0100 снова дал ответы 7E8/7E9. Обрывов TCP нет.
- **Это не проверка блока Gateway 19**, не найден список VAG-ЭБУ.
- Оказалось, что TXT-экспорт «VIN замаскирован» оставлял HEX-байты VIN
  в RAW ответе 0902. В 0.2.1 команды 0902 и 22F190 полностью скрываются
  в TXT, но оригинальный RAW остаётся в локальном Room; сообщения 03/07
  и CAN-адреса сохраняются в экспорте.
- Повторный автомобильный тест только из-за исправления экспорта не нужен.


## 0.2.2 — первая проверка TP2.0 на совместимой платформе

- Отдельный кодек `VagTp20Gateway` описывает опубликованную
  **CHANNEL SETUP** последовательность `0x200` к логическому
  адресу `0x19`, ожидает единственный ответ `0x219`, проверяет
  формат/валидность динамических CAN ID и отрицательные ответы.
- Никакого общего поиска адресов и никаких запросов KWP2000,
  UDS 19, 22, кодирования или стирания кодов неисправностей.
- Приложение автоматически распознаёт ограниченную платформу
  `1K` **по двум символам проверенного ответа OBD Mode09** вместе
  с Volkswagen WMI (в VIN-сводке и UI полный VIN не хранится).
  Для иных платформ этот экспериментальный TP2.0 шаг пропускается.
- Перед одним запросом настройки канала адаптер переводится
  во временный RAW CAN-режим `ATCAF0 / ATCFC0 / ATSH200 /
  ATCRA219` **в отдельной сессии**. После проверки исходный OBD
  режим вновь устанавливается; никакой новой пользовательской кнопки.
- Для Wi-Fi, Classic и BLE используется общий ElmEngine.
  Сведения `TP20_GATEWAY_CHANNEL_PROBE` сохраняются в журнал,
  а отказ считается отсутствием доказательства, не отсутствием блока.
- Результаты аппаратного теста 0.2.0 на стандартном OBD/ISO-TP
  не означают поддержку TP2.0; это новая функция, требующая
  одного реального испытания.
