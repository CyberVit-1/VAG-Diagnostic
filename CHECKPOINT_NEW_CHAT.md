## 4. ДОГОВОРЁННОСТИ ПОЛЬЗОВАТЕЛЯ

- Цель: рабочее, красивое Android приложение диагностики VAG (VW, Audi, Skoda, SEAT, CUPRA) с реальными ECU/DTC, статусами, историей, локальными/онлайн описаниями, поиском Яндекс. Не останавливаться на псевдодиагностике OBD двигателя.
- Тесты на JVM, Android build и симуляторы НЕ подтверждают работу с автомобилем. Только физический ELM+реальная машина+полный журнал дают право говорить «физически подтверждено».
- Не придумывать ECU, ошибки, ответы, VIN, тайминги, адреса, статусы. NO DATA / недоступность / отрицательный ответ НЕ равны «Ошибок нет». Partial scan сохраняется.
- ВСЕ диагностические функции должны быть общими для Wi-Fi TCP, Bluetooth Classic SPP, BLE (пока реализован Nordic UART/NUS). Разница только в реализации транспорта и фактических возможностях оборудования. Не делать Wi-Fi-only диагностических функций.
- Никаких отдельных пользовательских кнопок «проверить адаптер». Автоматические проверки только по необходимости, с гарантией корректного возврата к нормальному OBD.
- Только ЧТЕНИЕ: без clear DTC, программирования, кодирования, Security Access, адаптаций, опасных сессий/тестов. Никакого неограниченного CAN brute-force.
- VAG логический адрес Gateway 19 ≠ UDS сервис 0x19 ≠ стандартные ECU ответы 7E8/7E9. Нельзя называть стандартный OBD Auto-Scan-ом.
- Подробный RAW журнал в Room, сохранение на остановке и обрыве, экспорт TXT с маскированием VIN (в том числе hex-содержимого команд 0902 и 22F190).
- Wi-Fi ELM без интернета должен продолжать диагностику; для TCP использовать Android Network.socketFactory, не переключать целый процесс через bindProcessToNetwork. Интернет/Яндекс отдельно.
- Не обсуждать напряжение бортовой сети, если пользователь сам не попросил.
- Не заставлять ездить к машине после каждого маленького исправления. Работать максимально самостоятельно до одного содержательного аппаратного теста. При первом NO DATA/сбое сначала анализировать журнал.
- Постоянный applicationId com.vagdiagnostic.app. Не требовать держать старые отдельные пилотные APK.
- До удаления/переустановки/смены подписи предупредить: внутренние Room-история, настройки и RAW исчезнут при uninstall. Внешний TXT переживёт удаление, но НЕ является полной резервной копией Room. Сохранить нужные данные ДО потенциально разрушительного действия.
- Готовый APK выдавать прямо в чат при проверенном пути, не только GitHub ссылкой.
- Пользователь не любит длинные ответы на обычные вопросы: говорить КРАТКО. Каждый этап/релиз: «Что требуется от вас сейчас» и «Что дальше».

## 5. АРХИТЕКТУРА И ГОТОВЫЕ МОДУЛИ

- Kotlin + Jetpack Compose Material3; плиточный интерфейс, экраны подключения, диагностики, истории, настроек, сворачиваемые карточки ECU.
- MainViewModel.kt: StateFlow, оркестрация соединения/сканирования, отмена, сохранение неполных результатов, автоматические проверки Mode09 и временные адресные сессии.
- transport/ElmLink.kt, Links.kt: единый поток байт для Wi-Fi TCP (Network.socketFactory), Bluetooth Classic RFCOMM/SPP, BLE Nordic UART GATT.
- transport/ElmEngine.kt: AT init, сериализованный ELM command/response до prompt «>», таймауты, 0100, ATDPN, журнал.
- transport/ElmScanSession.kt: ограниченное восстановление read-only команд 0100/03/07/0A/0900/0902 для всех транспортов; Wi-Fi особая превентивная проверка простоя.
- core/DiagnosticCore.kt, VagUdsReadOnly.kt, VagAddressedCan.kt: строгий OBD, DTC, ISO-TP, UDS разбор, отрицательные ответы и ECU адресация.
- core/ObdMode09Readiness.kt и transport/ElmAddressedObdProbe.kt: стандартные 0900/0902, проверка многофреймового OBD и стандартного физического 7E0→7E8 (и подтверждённых пар).
- core/VagTp20Gateway.kt и transport/ElmTp20GatewayProbe.kt: однократная экспериментальная начальная настройка TP2.0 Gateway 19 только при подходящем VW 1K профиле. НЕ полный TP2.0, KWP, список блоков.
- core/ElmProtocolDescription.kt: в UI преобразует сырой ATDPN=A6 в ISO 15765-4 CAN (11 бит, 500 кбит/с) · Авто. В протокольной логике хранить исходный A6.
- core/DiagnosticLogRedactor.kt: защищённый экспорт журнала без VIN в ASCII/HEX.
- data/: Room журнал и история, DataStore настройки.
- .github/workflows/android.yml: Java17, Gradle8.11.1, SDK35, Android assembleDebug и unit tests.
- НЕ ГОТОВО: полноценный VAG Auto-Scan, действительное чтение Installation List, DTC всех OEM ECU, KWP1281, полный TP2.0/KWP2000. Не утверждать поддержку без физического доказательства.

## 7. ЧТО ИМЕННО ИЗМЕНИЛОСЬ В ВЕРСИИ 0.2.4

Публичные примеры ELM327/VW TP2.0 используют **USER1 raw CAN протокол B**, а не обычный авто ISO 15765-4 A6. В коде transport/ElmTp20GatewayProbe.kt:
1. Гейт: подтверждённое OBD 0100, CAN 11 бит 500 кбит/с, Mode09 VIN с Volkswagen WMI и маркером шасси 1K, успешный адресный стандартный 0902. Никаких CAN запросов к неподходящей платформе.
2. Отдельная disposable ELM-сессия: **ATPBC001 → ATSPB → ATCAF0 → ATCFC0 → ATV1 → ATAT0 → ATST96 → ATBI → ATSH200 → ATCRA219**.
3. Каждый AT ответ должен быть строго OK; при отказе остановить.
4. Проверка **ATDPN == B** после переключения. Если клон сообщает A6/6 или другое, **не посылать Gateway CAN**.
5. РОВНО ОДИН запрос настройки TP2.0 канала: CAN 0x200, payload 7 байт 19C00010000301. ELM ввод **19C000100003011**: последняя шестнадцатеричная цифра 1 задаёт максимум одного ответа и НЕ является байтом CAN данных.
6. Ожидаемый положительный ответ только на CAN **0x219** с правильной структурой D0 либо честный отказ/NO DATA; никаких KWP, DTC clear, «активаций» и сканирования адресов.
7. После эксперимента независимо от результата восстановить штатный OBD ATSP0/0100.
8. Это общий код поверх ElmEngine для Wi-Fi, SPP, BLE; аппаратных подтверждений других транспортов нет.
9. Unit tests проверяют ATPBC001/ATSPB/ATBI, ATDPN=B, отказ при неподдержанной команде, один raw setup, отсутствие опасных ECU команд.
10. GitHub CI зелёный **на 71d2735**. **На автомобиле 0.2.4 ЕЩЁ НЕ проверяли.** Даже положительный D0 подтверждает только открытие канала, а не Auto-Scan.

## 8. ЧТО ТРЕБУЕТСЯ ОТ ПОЛЬЗОВАТЕЛЯ СЕЙЧАС

**Одно реальное испытание 0.2.4**:
1. Сначала сохранить нужную локальную историю/RAW/настройки, если APK потребует uninstall из-за debug-подписи (внешний TXT не полноценный backup).
2. Установить 0.2.4 на телефон, подключиться к физическому ELM и автомобилю, выждать 20–30 секунд.
3. Выполнить ОДИН полный диагностический запуск.
4. Передать **полный экспорт TXT + один скриншот**. При NO DATA/ошибке НЕ повторять сразу.

Проверить в журнале: штатный OBD 0100/03/07/0A, 0900/0902, ADDRESSED_OBD_ISOTP, затем **ATPBC001, ATSPB, ATBI, ATDPN=B, ATSH200, ATCRA219, 19C000100003011, TP20_GATEWAY_CHANNEL_PROBE**, и в конце восстановление обычного ATSP0/0100. При неподходящем VW профиле TP2.0 должен быть пропущен.

## 9. ЧТО ДАЛЬШЕ ПО ЖУРНАЛУ 0.2.4

- Если команды USER1 отклонены, или ATDPN не B: искать реальное ограничение данного ELM-клона, не объявлять шлюз отсутствующим.
- Если ATDPN=B, но NO DATA: проверять протокол B/CAN physical, фильтрацию, DLC, маршрутизацию, доступность TP2.0 на данной платформе; **не перебирать вслепую CAN адреса**.
- Если принят D0 с адреса 0x219: доказано ТОЛЬКО согласование начального TP2.0 канала; следующая работа — полный read-only TP2.0/KWP2000 handshake, ACK/timing и документированное чтение Installation List. Не говорить, что Auto-Scan уже работает.
- Если нарушено штатное OBD после эксперимента: прежде всего исправить восстановление, сохраняя журналы и DTC.
- При обновлениях сначала читать текущую ветку и исходники, не возвращаться к устаревшим предположениям.
